1. 적용 범위와 계정

Asana에서 사용자가 볼 수 있는 태스크, 댓글, 반응과 팀 활동을 불러와 읽음 상태·북마크·개인 그룹과 함께 보여줍니다.

tedyway 자체 계정은 만들지 않습니다. Asana 계정과 Personal Access Token(PAT)이 필요합니다. CloudKit 권한이 있는 배포판에서 연결하고 Apple ID로 iCloud를 사용할 수 있으면 개인 상태 동기화를 자동으로 시도합니다.

2. 기기에서 처리·보관하는 데이터

  • Asana 태스크 이름·설명, 댓글 본문, 작성자·담당자·프로젝트·첨부·반응 정보와 Asana가 제공한 작성자 아바타를 포함한 화면 표시용 캐시
  • 읽음 기록, 최근 본 항목, 북마크, 고정한 사람·그룹, 봇/봇 아님 사용자 분류와 앱 설정
  • macOS Application Support 또는 iOS 앱 컨테이너의 캐시와 기기 내 UserDefaults 폴백
  • Core Spotlight 시스템 검색 설정은 이 기기에서 기본적으로 꺼져 있고 iCloud로 동기화되지 않습니다. 사용자가 명시적으로 켜고 사용 가능한 Asana 토큰이 있을 때에만 현재 캐시에서 중복을 제거한 최대 2,000개 항목의 태스크 이름·본문·댓글, 활동·작성자·프로젝트와 Asana 링크를 색인합니다.

3. Apple 서비스와 private 데이터 경계

  • PAT는 이 기기의 동기화되지 않는 Apple Keychain 항목에만 저장하며 iCloud Keychain, CloudKit 또는 iCloud KVS로 보내지 않습니다. Mac과 iPhone은 각각 연결해야 합니다.
  • 읽음·고정·그룹·북마크와 봇/봇 아님 사용자 분류 상태는 현재 Asana 사용자와 워크스페이스 범위로 분리되어 사용자의 private CloudKit 데이터베이스에 동기화될 수 있습니다. 작은 동기화 기준 설정에는 iCloud KVS를 사용할 수 있습니다.
  • private CloudKit 데이터는 해당 Apple ID의 영역이며 tedyway 운영자가 일반 서비스 데이터베이스처럼 조회하거나 대신 삭제할 수 없습니다.

4. 외부 서비스와 전송

  • Asana API: PAT 권한 범위 안의 워크스페이스·사용자·팀과 태스크 이름·설명, 댓글 본문, 첨부·반응 정보를 조회하고, 사용자가 명시적으로 실행한 댓글·좋아요·완료 등의 작업을 반영합니다.
  • 배포 Release에서는 AI 요약·인물분석과 사용자 지정 백엔드 경유 기능을 비활성화하므로 태스크·댓글 내용을 AI 제공자나 개발자 운영 백엔드로 보내지 않습니다.
  • 임의의 외부 링크 대상 페이지와 본문·첨부 이미지는 자동으로 불러오지 않습니다. Asana 태스크 링크 카드는 대상 웹사이트가 아니라 인증된 Asana API로 메타데이터를 자동 보강할 수 있습니다. 작성자 아바타는 Asana API가 제공한 HTTPS 이미지 주소에서 자동으로 내려받을 수 있으며 Asana 또는 해당 이미지 호스트가 IP 주소와 요청 정보를 각자의 정책에 따라 처리할 수 있습니다. 그 밖의 외부 링크·이미지는 사용자가 직접 열기 또는 이미지 불러오기를 실행할 때에만 접속합니다.
  • macOS 배포 Release는 Sparkle이 GitHub Releases의 서명된 appcast를 자동으로 확인합니다. 이때 GitHub가 IP 주소, User-Agent와 요청 메타데이터를 자체 정책에 따라 처리할 수 있습니다. 자동 설치는 하지 않으며 사용자가 업데이트를 선택하면 서명·공증된 DMG를 GitHub에서 내려받습니다.

5. 이용 목적

위 데이터는 각 항목에 적은 앱 기능과 사용자의 선택을 처리하는 데 사용됩니다. 이 앱에 존재하지 않는 계정·동기화 목적이나 현재 구현에서 확인되지 않은 광고·추적·판매 목적을 이 문서가 새로 부여하지 않습니다.

6. 보관

  • 로컬 캐시는 앱 기능 제공과 오프라인 표시를 위해 기기에 남으며 설정의 ‘연결 및 데이터 삭제…’ 또는 앱 컨테이너 제거의 영향을 받습니다.
  • 읽음 영수증은 60일·최대 5,000개로 제한합니다. 최근 본 항목은 기기 로컬에서 최대 1,000개로 제한합니다. 반응 관찰 기록은 과거 반응을 새 반응으로 오인하지 않도록 나이만으로 지우지 않고, 보존 피드·캐시 범위와 반응 20,000개·관측 태스크 10,000개 안전 상한으로 제한합니다. 북마크·사용자 그룹과 Asana 원본 데이터에는 같은 자동 삭제 기간을 약속하지 않습니다.
  • Core Spotlight 조정은 앱 시작·새로고침·더 불러오기 때 같은 기존 도메인의 삭제를 먼저 요청한 뒤, 명시적 동의와 사용 가능한 Asana 토큰이 모두 있으면 현재 캐시에서 중복을 제거한 최대 2,000개 항목으로 교체합니다.
  • 각 Core Spotlight 항목의 만료일은 해당 조정 시점부터 30일입니다. 색인과 삭제는 기기의 Core Spotlight에 보내는 비동기 요청이므로 실제 기기에서 최종 결과를 확인해야 합니다.
  • Asana 원본 데이터와 사용자가 직접 연 외부 사이트의 처리는 각 제공자 정책을 따릅니다. tedyway 운영자가 그 보관 기간을 대신 보증하지 않습니다.
  • GitHub 업데이트 확인·다운로드 요청의 서버 측 보관은 GitHub 정책을 따르며 tedyway 운영자가 그 기간을 대신 보증하지 않습니다.

7. 삭제와 사용자 선택

  • 앱 설정에서 ‘연결 및 데이터 삭제…’를 선택한 뒤 목적에 맞는 삭제 범위를 고릅니다.
  • ‘이 기기 연결만 해제’는 이 기기의 PAT, 피드 캐시, 이미지 캐시, 읽음·최근 본 항목·고정·그룹·북마크·봇 분류와 시스템 검색 색인을 정리합니다. private CloudKit 동기화 데이터는 남기므로 iCloud를 사용할 수 없는 기기에서도 로컬 연결을 끝내거나 새 계정을 연결할 수 있습니다.
  • ‘iCloud 동기화 데이터까지 삭제’는 위 기기 로컬 범위에 더해 그 시점에 접근 가능한 현재 Asana 사용자·워크스페이스 범위의 Asanagram private CloudKit 상태를 정리합니다. iCloud·Keychain·Spotlight 중 필요한 정리가 끝나지 않으면 완료로 표시하지 않고 복구 상태를 유지하므로 네트워크와 Apple ID를 확인한 뒤 같은 앱에서 재시도하거나 다시 실행합니다.
  • PAT는 기기 간 동기화하지 않으므로 Asanagram을 연결한 다른 Mac 또는 iPhone에서도 ‘이 기기 연결만 해제’를 각각 실행합니다. 다른 기기에서도 iCloud 삭제를 반복할 필요는 없지만 오프라인 때 남은 로컬 자료는 별도로 정리합니다.
  • Asana 개발자 설정에서도 해당 PAT를 별도로 폐기합니다. 두 삭제 기능 모두 Asana 계정이나 원본 태스크·댓글을 삭제하지 않습니다.
  • 시스템 검색을 끄거나 연결을 해제한 뒤 Spotlight 결과가 사라졌는지 실제 기기에서 확인합니다. Core Spotlight 삭제는 기기에 보내는 비동기 요청이며 실패하면 앱이 완료로 표시하지 않습니다.
  • 내부 Debug 빌드에서 ASANA_PAT 환경변수나 .env를 사용했다면 해당 값과 파일은 사용자가 직접 제거합니다. 배포 Release는 이 fallback을 읽지 않습니다.
  • ‘이 기기 연결만 해제’는 private CloudKit 레코드를 지우지 않습니다. 모든 동기화 상태까지 없애려면 iCloud를 사용할 수 있는 기기에서 ‘iCloud 동기화 데이터까지 삭제’를 선택합니다.
  • CloudKit 포함 삭제는 명령을 실행한 기기의 로컬 자료와 그 시점에 해당 Apple ID로 접근 가능한 현재 Asana 사용자·워크스페이스의 Asanagram private CloudKit 범위를 대상으로 합니다.
  • 다른 기기에 남은 로컬 캐시와 기기별 PAT는 원격으로 지울 수 없습니다. 각 기기에서 연결을 해제해야 하며, 오프라인이었던 다른 기기는 다시 연결하기 전에 별도로 확인해야 합니다.
  • 앱 삭제만으로 Keychain 또는 private CloudKit 데이터까지 삭제됐다고 간주하면 안 됩니다. 앱을 먼저 삭제했다면 Apple ID의 iCloud 저장 공간과 Asana PAT 설정도 별도로 확인합니다.
  • Core Spotlight와 CloudKit 삭제는 Apple 서비스의 비동기 처리·접근 가능 범위에 따릅니다. 앱이 실패를 표시한 경우 완료로 간주하지 말고 재시도해야 합니다.
  • Asana에 원래 존재하는 계정·태스크·댓글·첨부는 Asana에서 관리해야 하며, 지원 메일로 Apple private CloudKit 또는 Asana 계정 데이터를 대신 삭제할 수 없습니다.
